# Моделирование домена (CopyPaste)

Скилл для архитектора и разработчика. Помогает применять тактический DDD так, как
это принято в этом проекте, без карго-культа.

## Порядок работы

1. Прочитай `docs/ARCHITECTURE.md` (разделы 3–5) и
   `docs/UBIQUITOUS_LANGUAGE.md`.
2. Определи, к какому контексту относится изменение. Если нового контекста нет
   в карте — сначала проверь, нужен ли он вообще (правило «не создавать модуль
   заранее»).
3. Реши, где живёт поведение: агрегат → VO → доменная политика → use case.
4. Только потом думай о персистентности.

## Чек-лист агрегата

- У агрегата есть один корень и чёткая транзакционная граница.
- Поля меняются только через методы с доменными именами.
- Инварианты проверяются в момент изменения, а не в контроллере/форме.
- Нет публичных сеттеров и «анемичных» геттеров-сеттеров ради ORM.
- Ссылки на другие агрегаты — по идентификатору, не по объекту.

## Чек-лист value object

- `final readonly`, создаётся только через конструктор с валидацией.
- На невалидное значение — доменное исключение, не `false`/`null`.
- Никакой зависимости от Doctrine/Symfony.
- Равенство по значению, а не по идентичности.

## Чек-лист порта

- Интерфейс живёт на стороне потребителя (Domain/Application).
- Возвращает доменные типы, а не ORM/HTTP-типы.
- Для недетерминизма (время, случайность, шифрование) — отдельный порт, чтобы
  тесты были детерминированными.
- Реализация — в `Infrastructure`, регистрируется в DI.

## Чек-лист доменного события

- Имя в прошедшем времени: `SecretCreated`, `SecretBurned`.
- Событие фиксируется на агрегате; публикация — только когда появился реальный
  потребитель.
- Событие не заменяет прямой вызов use case, пока нет второго подписчика.

## Красные флаги

- `Manager`, `Helper`, `Util`, `Processor` в имени класса.
- ORM-атрибуты или импорт Doctrine/Symfony в `Domain`.
- Бизнес-логика в контроллере, форме или Doctrine-репозитории.
- Ожидаемая бизнес-альтернатива, выраженная исключением.
- Публикация событий «на будущее», без потребителя.
- VO, которое ничего не валидирует и не имеет поведения.
- Протечка `QueryBuilder`/`EntityManager` за пределы адаптера.
