# CONVENTIONS.md

Соглашения по коду CopyPaste. Обязательны для всех агентов и людей. Дополняют
`docs/ARCHITECTURE.md` и не дублируют его.

## 1. Общие правила PHP

- В каждом PHP-файле первой строкой после `<?php` — `declare(strict_types=1);`.
- Классы `final` по умолчанию. Наследование — только осознанно (исключения,
  базовые абстракции фреймворка).
- Целевая версия — PHP 8.4. Используй современный синтаксис: constructor
  property promotion, `readonly`, named arguments, enum, match.
- Иммутабельность по умолчанию: `readonly` для VO и DTO, запрет сеттеров в
  домене. Изменяемое состояние агрегата меняется только через методы с
  осмысленным именем.
- Явные типы у свойств, параметров и возвращаемых значений. `mixed` — только на
  границе с нетипизированной внешней системой, с сужением типа сразу.
- Строгое сравнение `===`/`!==`, `declare(strict_types=1)`.
- Без комментариев, если код самодостаточен. Комментарий оправдан только для
  неочевидного «почему», а не «что».

## 2. Нейминг

- Классы — PascalCase, методы/переменные — camelCase, константы — UPPER_SNAKE.
- Имена отражают **домен**, а не технику: `Secret`, `Token`, `Ttl`, а не
  `PasteManager`, `DataHelper`, `StringUtil`.
- Запрещены суффиксы `Manager`, `Helper`, `Util`, `Processor`. Если хочется
  такой суффикс — скорее всего, ответственность размыта.
- Суффиксы слоёв: `*Controller`, `*Type` (форма), `*Command` (консоль или
  use case — различать по namespace), `Handler` (обработчик use case),
  `*Repository` (порт и адаптер), `*Exception`, `*Test`.
- Use case называем глаголом в повелительном наклонении: `CreateSecret`,
  `RevealSecret`, `PurgeExpiredSecrets`.
- Тесты: `test<Поведение><Ожидание>` в стиле
  `testWrongKeyShowsNeutralError()`.

## 3. Слои и импорты

- `Domain` не импортирует Symfony, Doctrine, Twig, Sodium.
  Единственные допустимые внешние импорты — PHP SPL, `Psr\*`, `Shared\Domain`.
- `Application` импортирует `Domain` и порты. Не импортирует `Symfony\Component\HttpFoundation`.
- `Infrastructure` реализует порты и может импортировать всё нужное.
- `Presentation` не импортирует `Infrastructure` напрямую: только сервисы
  Application/Domain через DI.
- Проверка — deptrac в `make deptrac` (см. `docs/QUALITY.md`).

## 4. Symfony

- Внедрение зависимостей — через конструктор. `#[Required]` и service locator
  запрещены, кроме узаконенных случаев фреймворка.
- Контроллер тонкий: принять запрос → связать форму/валидировать → вызвать
  use case → отдать ответ. Бизнес-логики и `persist/flush` в контроллере нет.
- Маршруты — атрибутами в `Presentation/Http`, рядом с контроллером.
- Конфигурируемые значения (TTL, лимиты KDF) — через параметры/bindings в
  `config/services.yaml`, не через `getenv()` в коде.
- Формы и DTO валидируются через Symfony Validator; сообщения об ошибках для
  пользователя — на русском, нейтральные (не раскрывают наличие/отсутствие
  записи и детали ключа).

## 5. Doctrine

- Доменные классы не содержат ORM-атрибутов.
- Маппинг персистентности — в `Infrastructure/Persistence/Doctrine`. Для
  нетривиальных VO — persistence-модель + маппер.
- Репозитории — адаптеры портов. QueryBuilder не выходит за пределы адаптера.
- Миграции коммитятся вместе с изменением модели. Руками расхождения схемы и
  модели не правятся.
- Ни один SQL/DDL не выполняется из `Domain`/`Application`.

## 6. Ошибки и результат

- Нарушение инварианта → доменное исключение под `Domain/Exception`.
- Ожидаемая бизнес-альтернатива (неверный ключ, истёкшая запись) → элемент
  типизированного результата, а не исключение и не `null` без контекста.
- HTTP-статусы определяются в `Presentation`. Домен не знает про 404/422.
- Логирование: без plaintext, секретного ключа, производного ключа, salt/nonce
  в открытом виде. Ошибки криптографии логируются нейтрально.

## 7. Тесты

- Расположение зеркалит `src`: `tests/Unit/<Модуль>/<Слой>`, `tests/Functional`.
- Один тест — одно поведение. Структура Arrange–Act–Assert.
- Домен/Application — без моков конкретных классов; используются in-memory
  реализации портов и фиксированные `Clock`/`TokenGenerator`.
- Не тестировать приватные методы; тестировать поведение через публичный API.
- Не мокать value objects.
- Названия тестов описывают поведение и бизнес-последствие, а не метод.
- Обязательное покрытие для домена — см. `docs/QUALITY.md`.

## 8. Коммиты и PR

- Conventional commits: `feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `ci:`,
  `docs:`.
- Атомарность: один коммит — одно логическое изменение. Миграция идёт вместе с
  моделью.
- Язык сообщений — английский. Документы и обсуждения — русский (см.
  `docs/task/README.md`).
- Коммит и push выполняет человек после гейта G3. Агенты не пушут и не деплоят.

## 9. Форматирование

- PHP-CS-Fixer, пресет `@Symfony` + правила из `docs/QUALITY.md`.
- Отступ — 4 пробела, перенос строки — LF, кодировка — UTF-8.
- Форматирование не обсуждается в ревью: его обеспечивает `make cs-fix`.
