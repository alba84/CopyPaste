# 002-extract-create-secret: Эталонное извлечение use case `CreateSecret` в модуль `Secret`

> Статус: **G1 пройден.** Требования и решения Q1–Q6 утверждены человеком
> (все рекомендации A) — см. «Решения, утверждённые на G1».

## Контекст и проблема

CopyPaste сейчас — плоский монолит (`docs/ARCHITECTURE.md` §2): сценарий
создания записи целиком живёт в `App\Controller\PasteController::create()` —
генерация токена `bin2hex(random_bytes(16))` с проверкой уникальности, rate
limiting, расчёт TTL `now + P{pasteTtlDays}D`, вызов Sodium и `persist`/`flush`
в одном методе. Домена как слоя нет:

- агрегат `App\Entity\Paste` жёстко связан с Doctrine-атрибутами;
- `App\Dto\EncryptedPayload` — изменяемый DTO без поведения и инвариантов;
- `App\Service\EncryptionService` — конкретная реализация Sodium без порта;
- `App\Dto\CreatePasteData` / `App\Form\CreatePasteType` — валидация и ввод.

Из-за этого границы модулей нечем проверять, а сценарий нельзя тестировать без
контейнера. `docs/ARCHITECTURE.md` §9.3 назначает именно `CreateSecret` первой
задачей-шаблоном, а `docs/task/ROADMAP.md` — задачей 002. Маленькая кодовая
база — лучший момент зафиксировать эталон структуры, пока сценариев мало.

**Ключевое ограничение.** Сценарий открытия (Reveal) в этой задаче **не
мигрирует** и остаётся на легаси-классах (`PasteController::view`,
`PasteRepository`, `EncryptionService`). Поэтому новый путь создания обязан
быть совместим со старым путём чтения: та же таблица/схема (по умолчанию) и
байт-идентичный формат шифрования. Иначе после релиза 002 нельзя будет открыть
только что созданную запись.

## Пользовательская цель

Как мейнтейнер/разработчик CopyPaste, я хочу, чтобы сценарий создания Secret
был извлечён в модуль `Secret` по целевому шаблону (Domain/Application/
Infrastructure/Presentation), а внешнее поведение осталось неизменным, чтобы:

- последующие сценарии (Reveal, Purge, Access) мигрировали по готовому образцу,
  а не изобретали структуру заново;
- домен можно было тестировать без контейнера и фреймворка;
- границы и типы проверялись автоматически (`deptrac`, PHPStan L10), а не
  только на ревью.

Как пользователь сервиса, я хочу, чтобы после миграции создание ссылки,
маршруты/URL, тексты ошибок, лимиты и возможность открыть запись по ссылке
**не изменились**.

## Объём (in scope)

1. **Каркас модулей**: `src/Secret/{Domain,Application,Infrastructure,
   Presentation}`, `src/Crypto/{Domain,Infrastructure}`, `src/Shared` — только
   каталоги/namespace, нужные этой задаче; без преждевременных контекстов.
2. **Домен создания** (`Secret/Domain/Model`): агрегат `Secret`; VO `Token`,
   `Ttl`, `Hint`, `Plaintext`, `SecretKey`, `EncryptedPayload` — иммутабельные,
   самовалидирующиеся, с доменными исключениями под `Secret/Domain/Exception`.
   Инварианты: валидный токен; непустые plaintext/secret в допустимых длинах;
   hint нормализуется как сейчас; `expiresAt = createdAt + Ttl`.
3. **Доменные события**: `SecretCreated` фиксируется на агрегате. Публикация в
   шину **не** вводится (`docs/ARCHITECTURE.md` §4.1).
4. **Порты**:
   - `Crypto/Domain/Cryptography` — шифрование (и, при необходимости для
     совместимости, расшифровка);
   - `Secret/Domain/Repository/SecretRepository` — сохранение/чтение агрегата;
   - `Clock` (`Psr\Clock\ClockInterface`) — получение текущего времени;
   - `TokenGenerator` — генерация токена с гарантией уникальности.
5. **Адаптеры**:
   - Sodium-адаптер `Cryptography` в `Crypto/Infrastructure/Sodium`, полностью
     совместимый с текущим `EncryptionService`;
   - Doctrine-адаптер `SecretRepository` в
     `Secret/Infrastructure/Persistence/Doctrine` — persistence-модель + явный
     маппер для VO/BLOB (`docs/ARCHITECTURE.md` §5, см. Q1).
6. **Application**: use case `CreateSecret` (команда → обработчик → результат) в
   `Secret/Application/CreateSecret`; генерация токена, расчёт TTL, вызов
   криптографии и сохранение — здесь, не в контроллере.
7. **Presentation**: тонкий контроллер(ы) создания и форма в
   `Secret/Presentation/Http`; маршруты `app_home` (`/`) и
   `app_paste_created` (`/created/{token}`) с прежними именами/URL; шаблоны
   `paste/create.html.twig` и `paste/created.html.twig` используются без
   изменения вёрстки.
8. **Легаси**: у `PasteController` удаляется только `create` (его маршрут `/`
   переезжает в новый Presentation). `created` и `view`, а также `Paste`,
   `PasteRepository`, `EncryptionService`, `Unlock*`,
   `PurgeExpiredPastesCommand` остаются как есть и продолжают работать
   (согласовано с Q6-A на G1/G2; см. «Уточнение противоречия» в `plan.md`).
9. **deptrac**: добавить слои `Secret_*`, `Crypto_*`, `Shared` с целевыми
   правилами; легаси-слои `App\*` сохранить (см. Q4).
10. **Конфигурация**: TTL (`APP_PASTE_TTL_DAYS`) и лимиты KDF
    (`APP_KDF_OPSLIMIT`/`APP_KDF_MEMLIMIT`) остаются параметрами; добавляются
    bindings для `Clock`/`TokenGenerator`/портов.
11. **Тесты**: unit для Domain/Application (изолированно, in-memory порты);
    functional — существующие сценарии создания/открытия/ошибок/404/валидации
    без изменения ожиданий.
12. **Миграции/схема**: по умолчанию **без изменений** (см. Q2).
13. **Документы задачи**: этот `requirements.md`.

## Вне объёма (out of scope)

- **Reveal** (`PasteController::view`, `UnlockPasteType`/`UnlockPasteData`,

- **Purge** (`PurgeExpiredPastesCommand`, `PasteRepository::purgeExpired`) —
  задача 004.
- **Rate limiting** как контекст `Access`: лимиты остаются в Presentation в
  текущем виде; вынос — задача 006.
- **Удаление легаси-классов** (`PasteController`, `App\Entity\Paste`,
  `PasteRepository`, старые Dto/Form, `EncryptionService`) — задача 005.
- Новые контексты `Identity`, `Audit`, `Notification`, `Attachments`; event bus
  / eventual consistency.
- Смена СУБД, CQRS, микросервисы и прочее из `docs/ARCHITECTURE.md` §4.3.
- **Изменение крипто-формата** (KDF, алгоритм, параметры, длины, маркер
  версии) — см. Q3.
- Изменение публичного API/маршрутов, текстов ошибок, формата ссылок.
- Переименование таблицы `paste` → `secret` — по умолчанию вне объёма
  (см. Q2).

## Доменные термины (новые/уточнённые)

**Новых доменных терминов нет.** Задача использует уже зафиксированные
`docs/UBIQUITOUS_LANGUAGE.md` термины: `Secret`, `Plaintext`, `SecretKey`,
`Hint`, `Token`, `Ttl`, `Expiration`, `EncryptedPayload`, `Cryptography`,
`Reveal` (как ещё не мигрированный сценарий).

- Имена портов и механизмов (`Clock`, `TokenGenerator`, `SecretRepository`,
  имена классов/Symfony/Doctrine, `deptrac`) — **технические** и в глоссарий не
  добавляются.
- Доменные события `SecretCreated`/`SecretRevealed`/`SecretBurned`/
  `SecretExpired` — это композиции существующих терминов; `docs/ARCHITECTURE.md`
  §4.1 уже их описывает. Новыми значениями они не являются.
- Легаси-термин `Paste` в новом коде **не используется** (колонка
  «Не использовать»), но остаётся в легаси до задачи 005.

Следствие: `docs/UBIQUITOUS_LANGUAGE.md` **не изменяется**.

## Критерии приёмки (Given–When–Then)

**AC1 — Публичный контракт создания неизменен.**
Given приложение запущено,
When клиент открывает `GET /` и отправляет форму с полями
`create_paste[text]`, `create_paste[hint]`, `create_paste[secret]` и CSRF-токеном
`create_paste`,
Then валидная отправка даёт `302` на `app_paste_created` (`/created/{token}`),
токен соответствует `[a-f0-9]{32}`, а страница `/created/{token}` отдаёт
абсолютную ссылку на `app_paste_view` (`/p/{token}`); имена маршрутов и URL не
изменились.

**AC2 — Создание выполняет use case, а не контроллер.**
Given Presentation-контроллер создания и Application `CreateSecret`,
When приходит валидная форма,
Then создаётся агрегат `Secret` с токеном, hint, `EncryptedPayload`,
`createdAt` и `expiresAt = createdAt + Ttl`; событие `SecretCreated`
зафиксировано на агрегате; запись сохранена ровно один раз; повторная генерация
использует проверку уникальности токена.

**AC3 — Формат шифрования байт-совместим.**
Given plaintext, secret и сгенерированные salt/nonce,
When шифрует новый Sodium-адаптер,
Then ключ выводится `sodium_crypto_pwhash` (алгоритм
`SODIUM_CRYPTO_PWHASH_ALG_ARGON2ID13`, ops/mem из конфигурации), шифр —
`sodium_crypto_secretbox`; длины salt/nonce равны
`SODIUM_CRYPTO_PWHASH_SALTBYTES`/`SODIUM_CRYPTO_SECRETBOX_NONCEBYTES`; результат
побайтово совместим: запись, созданная новым путём, расшифровывается
существующим `EncryptionService`, и наоборот.

**AC4 — Интероп с легаси Reveal.**
Given Secret, созданный новым сценарием,
When получатель открывает `/p/{token}` и вводит верный ключ через легаси-код,
Then plaintext успешно показывается; отдельно проверяется, что Secret,
созданный легаси-путём, читается новым persistence-адаптером (если такой метод
предусмотрен решением Q1).

**AC5 — Неизменность схемы БД.**
Given решение G1 по таблице (Q1/Q2),
When выполняется `doctrine:schema:validate --env=test` и
`make migrate` на чистой БД,
Then схема соответствует маппингу и миграциям; имя таблицы и колонки не
изменились (или изменены ровно в объёме решения G1); существующие записи не
теряются.

**AC6 — Валидация и тексты ошибок неизменны.**
Given пустой `text`, пустой `secret` или превышение длин,
When форма отправлена,
Then ответ `422` и сообщения: «Введите текст», «Введите секретный ключ», «Текст
не должен превышать 100 000 символов», «Подсказка не должна превышать 255
символов», «Ключ не должен превышать 255 символов» — в тех же полях формы.

**AC7 — Hint нормализуется как прежде.**
Given hint `''` или строка только из пробелов,
When Secret создаётся,
Then подсказка хранится как `null`; для непустого после `trim()` hint
сохраняется исходное значение (не обрезанное); отображение на `/created` и `/p`
не меняется.

**AC8 — Rate limiting сохранён.**
Given лимитер `create_paste` (10 запросов / 1 минута),
When за минуту приходит 11-я попытка,
Then форма показывает «Слишком много запросов. Попробуйте через минуту.», и
запись не создаётся; лимитирование остаётся в Presentation и не входит в
Domain/Application (перенос — задача 006).

**AC9 — Presentation тонкий.**
Given исходники Presentation создания и Application `CreateSecret`,
When ревьюер проверяет контроллер,
Then в нём нет генерации токена, расчёта TTL, вызовов Sodium, `persist`/`flush`;
он только принимает запрос, связывает/валидирует форму и вызывает use case.

**AC10 — Границы слоёв соблюдены.**
Given `deptrac.yaml` с добавленными слоями `Secret_*`, `Crypto_*`, `Shared`,
When выполняется `make deptrac`,
Then команда выходит с кодом 0 без нарушений; `Domain`/`Application` не
импортируют Symfony/Doctrine/Sodium; `Crypto_Domain` не импортирует
`Crypto_Infrastructure`; `Presentation` не импортирует `Infrastructure`.

**AC11 — Легаси не сломан.**
Given существующие сценарии Reveal/Purge на легаси-классах,
When выполняется `make test` (`PasteFlowTest` и др.),
Then создание, открытие, неверный ключ, 404 и валидация проходят без изменения
ожиданий; правки тестов допускаются только технические (namespace/импорт/типы),
без смены наблюдаемого поведения.

**AC12 — Покрытие Domain/Application.**
Given `src/Secret/Domain` и `src/Secret/Application` и
`tools/check-coverage.php`,
When выполняется `make coverage`,
Then покрытие этих каталогов **≥ 90%** (`docs/QUALITY.md` §2.4), а `make qa`
зелёный.

**AC13 — Доменные события фиксируются, но не публикуются.**
Given агрегат `Secret`,
When происходит создание,
Then `SecretCreated` доступно через агрегат, и в проекте нет публикации
событий в шину/`MessageBus` для этого сценария.

**AC14 — Токен безопасен и уникален.**
Given коллизия уже существующего токена,
When use case создаёт Secret,
Then генерируется другой токен и в хранилище нет дубликата; формат токена —
32 hex-символа (криптостойкая случайность), совместимый с requirement маршрута
`[a-f0-9]{32}`.

**AC15 — Zero-error качество.**
Given новые исходники `src/Secret`, `src/Crypto`, `src/Shared`,
When выполняется `make qa` (`cs-check`, `stan` L10, `deptrac`, `test`) и
`make coverage`,
Then все шаги зелёные; baseline отсутствует; `@phpstan-ignore` — только
точечно, с причиной и датой (как в 001).

## Открытые вопросы (и ответы человека)

> **Гейт G1 пройден.** Объём, критерии и решения по Q1–Q6 подтверждены
> человеком. Архитектор переходит к `plan.md`.

### Вопросы, требующие решения человека на G1

1. **Q1 — стратегия персистентности** нового `Secret` при живом легаси Reveal
   (persistence-модель + маппер vs XML-маппинг vs переиспользование легаси
   сущности).
2. **Q2 — переименование таблицы** `paste` → `secret` и миграция существующих
   данных: делать в 002 или отложить в 005.
3. **Q3 — крипто-формат**: подтвердить неизменность (байт-совместимость без
   версионирования); учесть риски изменения формата.
4. **Q4 — deptrac**: как включать целевые слои при сохранении легаси-as-is.
5. **Q5 — wire-контракт формы** (`create_paste[...]`, `csrf_token_id`) при
   переименовании классов Presentation в терминологию Secret.
6. **Q6 — объём Presentation и rate limiting**: `created` и чтение Secret;
   остаётся ли лимитирование в контроллере до 006.

### Исходные вопросы с вариантами

**Q1. Куда и как пишет новый Doctrine-адаптер `SecretRepository`, если Reveal
ещё читает `paste` через легаси `App\Entity\Paste`?**
`docs/ARCHITECTURE.md` §5 предписывает persistence-модель + явный маппер для
агрегата с VO/BLOB, но одновременный маппинг двух классов на одну таблицу —
риск дрейфа `doctrine:schema:validate`.

- **A (рекомендую).** Отдельная persistence-модель + явный маппер в
  `Secret/Infrastructure/Persistence/Doctrine`, отображаемая на **ту же**
  таблицу `paste` и колонки; легаси `Paste` остаётся единственным ORM-классом,
  читающим её. Перед G2 проверить, что два маппинга не ломают `schema:validate`;
  при конфликте — перейти к B.
- **B.** Транзитный Doctrine-адаптер переиспользует легаси `App\Entity\Paste`
  как persistence-запись (Anti-Corruption Layer): маппер раскладывает VO →
  `Paste`. Гарантирует один маппинг и интероп; зависимость
  `Infrastructure → App\Entity` временная и удаляется в 005.
- **C.** Новая таблица `secret` + persistence-модель + миграция данных, легаси
  Reveal перенаправляется на неё. Затрагивает out-of-scope Reveal; не
  рекомендую в 002.

**Q2. Переименовывать ли таблицу `paste` в `secret` в рамках 002?**
Существующие данные и легаси Reveal привязаны к имени `paste`; миграция БД —
триггер эскалации к человеку.

- **A (рекомендую).** Оставить имя таблицы `paste` в 002 без миграции;
  переименование и миграцию данных выполнить в 005, когда Reveal тоже уйдёт.
- **B.** Переименовать сейчас (`ALTER TABLE paste RENAME TO secret`) и
  перенастроить легаси `Paste`/`PasteRepository` на новое имя — расширяет объём
  и трогает легаси.
- **C.** Оставить `paste` как основную, а новый `secret` ввести как
  представление/совместимость — избыточно и рискованно.

**Q3. Допустимо ли менять крипто-формат?**
От формата зависит, прочитает ли легаси Reveal (и уже сохранённые записи) то,
что создаст новый путь.

- **A (рекомендую).** Никаких изменений: Argon2id (`ARGON2ID13`, ops/mem из
  env), `sodium_crypto_secretbox`, штатные длины salt/nonce, без маркера
  версии и новых полей. Легаси `EncryptionService` — эталон совместимости.
- **B.** Ввести версионирование payload/шифра — потребует изменения чтения
  (легаси Reveal) и, возможно, схемы; вне объёма 002.
- **C.** Сменить KDF/алгоритм/параметры — отклоняется: делает старые и/или
  новые записи нечитаемыми.

**Q4. Как менять `deptrac.yaml` в 002?**
Легаси-код остаётся (005), но появляются целевые модули.

- **A (рекомендую).** Добавить слои `Secret_Domain/Application/Infrastructure/
  Presentation`, `Crypto_Domain/Infrastructure`, `Shared` с целевыми правилами;
  легаси-слои `App\*` сохранить без изменений. Новый код обязан соответствовать
  целевым правилам уже сейчас.
- **B.** Сразу перевести `deptrac.yaml` на полностью целевой набор, легаси
  пометить uncovered/skip — смешивает 002 и 005.
- **C.** Отложить правки deptrac до 005 — тогда AC10 недоказуем (не
  рекомендую).

**Q5. Как сохранить HTTP-контракт формы при переименовании классов в
терминологию Secret?**
Symfony выводит имя формы/полей из имени класса: `CreatePasteType` →
`create_paste[...]`; `create_secret[...]` — это observable-изменение
контракта и правка functional-тестов.

- **A (рекомендую).** Переименовать классы в Secret-терминологию, но явно
  сохранить block prefix `create_paste` и `csrf_token_id: create_paste`, чтобы
  поля/токен и ссылки не менялись.
- **B.** Сменить контракт на `create_secret[...]` — чище по словарю, но это
  изменение публичного поведения и обновление тестов (противоречит инварианту).

**Q6. Где рендерится `created` и где остаётся rate limiting?**
`app_paste_created` показывает срок и ссылку; `created` читает запись.

- **A (рекомендую).** Оставить `created` в легаси-контроллере на
  `PasteRepository` (согласовано с Q1-A: та же таблица); rate limiting остаётся
  в Presentation до задачи 006; `CreateSecret` о лимитах не знает.
- **B.** Перенести `created` в новый Secret-Presentation и читать через

## Нефункциональные требования и риски

### Нефункциональные требования

- **Безопасность.** Запрещено логировать/хранить plaintext, `SecretKey`,
  производные ключи, salt/nonce; не ослабляются CSRF (`csrf_token_id`
  `create_paste`), rate limiting, проверки TTL и (для Reveal)
  `Cache-Control: no-store`; KDF-лимиты и TTL остаются конфигурируемыми через
  env; `.env.local` не коммитится.
- **Неизменность поведения.** Маршруты/имена маршрутов/URL, формат ссылок,
  тексты ошибок, имена полей формы, формат шифрования, схема БД (по умолчанию)
  не меняются; существующие functional-тесты остаются валидными.
- **Совместимость.** PHP 8.4, Symfony 7.4; `Clock` — `Psr\Clock\ClockInterface`
  (пакеты `psr/clock` и `symfony/clock` доступны транзитивно); Doctrine ORM 3;
  `doctrine:schema:validate --env=test` зелёный.
- **Тестируемость.** Domain/Application тестируются без контейнера через
  in-memory порты и фиксированные `Clock`/`TokenGenerator`
  (`docs/ARCHITECTURE.md` §7); инфраструктура — интеграционно.
- **Качество.** `make qa` зелёный: `cs-check` без правок, PHPStan L10 ноль
  ошибок, `deptrac` без нарушений, `test` зелёный; покрытие
  `src/Secret/Domain` и `src/Secret/Application` ≥ 90% (`docs/QUALITY.md` §2.4)
  — с появлением этих каталогов условный порог из 001 начинает действовать.
- **Обозримость diff.** Изменения только в объёме 002; легаси-классы вне
  перенесённого сценария не переписываются; каждый шаг обратим.
- **Локализация.** Пользовательские сообщения — русские, нейтральные, ровно
  как сейчас.

### Риски

| Риск | Влияние | Митигация |

| Два Doctrine-маппинга на таблицу `paste` дают дрейф/конфликт схемы | `schema:validate` падает, возможна потеря/несовместимость данных | Q1; проверка на G2; fallback на ACL (Q1-B) или новую таблицу (Q1-C) |
