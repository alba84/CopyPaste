# 006-rename-paste-table-to-secret: переименование таблицы `paste → secret` одной миграцией

> Источник: `docs/task/ROADMAP.md` §006, ADR 0002 («005 при удалении легаси
> переименует `paste → secret` одной миграцией»), ADR 0003 (anchor будет
> переименован/удалён в 005b). Задача — `005b` из разбиения 005: 005a удалила
> легаси-слой `App\*` **без миграции**; 006b — единственная задача, которой
> разрешено менять схему БД.

## Контекст и проблема

005a удалила легаси-бизнес-код `App\*` и вынесла сценарии в модуль `Secret`
(`CreateSecret`, `RevealSecret`/`LoadRevealSecret`, `PurgeExpiredSecrets`,
`created`). Персистентность работает так (ADR 0002):

- Рантайм — DBAL-адаптер `DoctrineSecretRepository` поверх
  `Doctrine\DBAL\Connection`; persistence-модель `SecretRecord` + явный
  `SecretRecordMapper`; **ручной SQL по таблице `paste`**.
- Владение ORM-метаданными — технический schema-anchor
  `PasteSchemaAnchor` (`#[ORM\Table(name: 'paste')]`), введённый ADR 0003
  только ради `SchemaTool` и `doctrine:schema:validate`; сервисом не является.
- Единственная миграция `migrations/Version20260909000000.php` создаёт `paste`
  с колонками `id/token/hint/salt/nonce/ciphertext/created_at/expires_at`,
  unique-индексом на `token` (имя сгенерировано Doctrine:
  `UNIQ_9C5678985F37A13B`) и индексом `idx_paste_expires_at`.

В результате терминология «Secret» доведена до кода, но **физическая схема и
часть технических имён всё ещё используют легаси-термин `Paste`**. Задача 006
закрывает этот разрыв: отдельной, обратимой миграцией переименовать таблицу
`paste → secret`, сохранив **все строки и всё наблюдаемое поведение**, и
синхронизировать имена в коде/тестах/конфиге. Публичные имена (маршруты,
команда, wire-контракты форм, тома Docker) по умолчанию **не трогаются** —
это отдельное решение (см. Q3).

Дополнительно 005 отложила вопрос Q1-C: переходить ли на migrations-only и
удалять ORM-anchor. 006b — естественная точка, чтобы принять или явно отложить
это решение (см. Q1).

### Ключевые технические факты (проверено по коду/vendor)

1. **SQLite `ALTER TABLE ... RENAME TO`** доступен с SQLite 3.25 (2018). В
   `php:8.4-fpm-alpine` и на `ubuntu-latest` CI версия существенно новее; на
   этапе плана требуется зафиксировать фактическую версию
   (`PDO::ATTR_SERVER_VERSION` / `sqlite3_libversion()`), чтобы исключить
   окружение со старым SQLite. Rename — операция уровня метаданных, строки не
   переписываются.
2. **Индексы после rename сохраняются, но имена не меняются.** SQLite не имеет
   `ALTER INDEX ... RENAME`; переименование индекса возможно только
   `DROP INDEX` + `CREATE [UNIQUE] INDEX`.
3. **Ловушка unique-индекса `token`.** Doctrine ORM генерирует имя unique-индекса
   из **имени таблицы** и колонок (`Doctrine\DBAL\Schema\AbstractAsset::
   _generateIdentifierName`). Поэтому смена таблицы на `secret` при
   `#[ORM\Column(unique: true)]` меняет ожидаемое метаданными имя
   (`UNIQ_<hash(secret,token)>`), а физический индекс после rename остаётся
   `UNIQ_9C5678985F37A13B` → `doctrine:schema:validate` видит
   `addedIndexes/droppedIndexes`/`renamedIndexes` и падает (exit 2,
   `SchemaDiff`/`TableDiff::isEmpty` учитывает `renamedIndexes`).
   **Вывод:** имена индексов в ORM-метаданных и в БД обязаны совпадать —
   либо явно закреплены в anchor, либо физически переименованы миграцией.
4. **`make test` миграции не выполняет**: тесты создают схему через `SchemaTool`
   по ORM-метаданным (anchor). CI (`.github/workflows/ci.yml`) выполняет
   `doctrine:migrations:migrate -n --env=test` → `doctrine:schema:validate
   --env=test` → `phpunit`. После 006 обе среды должны давать `secret`.
5. **Prod-путь обновления** (`deploy/deploy.sh`): бэкап `app.db` →
   `doctrine:migrations:migrate -n` → старт. Миграция исполняется на **живой
   БД self-hosted с данными**; бэкап есть, но `down()` при откате релиза
   автоматически **не** вызывается (см. риски).
6. **Docker-том** называется `paste_data` (`compose.prod.yaml`,
   `deploy/deploy.sh`). Его переименование осиротит данные существующих
   установок (поднимется пустой том) — вне объёма 006.
7. **Историческая миграция неизменна.** `Version20260909000000` остаётся
   как есть (на своём шаге истории она создаёт `paste`); переименование —
   новая миграция строго позже.

## Пользовательская цель

Self-hosted оператор обновляет CopyPaste на релиз с 006 и после
`doctrine:migrations:migrate` получает ту же самую базу, но с таблицей `secret`:
все ранее созданные Secret по-прежнему открываются и расшифровываются ровно как
раньше, ссылки/формы/лимиты/тексты не меняются, а схема и технические имена
соответствуют терминологии `Secret`. Миграция применяется с нуля и
откатывается; на БД с данными не теряется ни одной строки.

## Объём (in scope)

1. **Новая миграция** `migrations/Version<позже 20260909000000>.php`
   (`up`/`down`), которая:
   - переименовывает `paste` → `secret`;
   - согласует индексы так, чтобы метаданные anchor и БД совпадали (конкретный
     вариант имён — Q2);
   - сохраняет колонки, типы, nullability и все строки;
   - в `down` возвращает точную предыдущую схему (таблица `paste`, исходные
     имена индексов), чтобы повторный `up` был возможен.
2. **Синхронизация кода:** `DoctrineSecretRepository` (SQL), anchor (имя
   таблицы, имена индексов; при Q1-A — переименование класса в
   `SecretSchemaAnchor`).
3. **Синхронизация тестов:** все обращения к таблице `paste` в `tests/` →
   `secret`; переименование `PasteSchemaAnchorTest`; **новый** интеграционный
   тест, доказывающий сохранение данных при `up`/`down` миграции.
4. **Документы:** `ROADMAP.md` (006), ADR по Q5 (короткий ADR 0004 и/или
   правка ADR 0003/0002 — по решению), `requirements.md`/`plan.md`/`review.md`.

## Доменные термины (новые/уточнённые)

**Новых доменных терминов нет.** `Secret`, `Token`, `EncryptedPayload`,
`Expiration`, `SecretRepository`, `Purge` уже зафиксированы. `Paste`
перестаёт быть именем физической таблицы, но остаётся только как наблюдаемый
легаси-идентификатор (route/command/wire/volume) до отдельного решения.

**`docs/UBIQUITOUS_LANGUAGE.md` не изменяется.** Целевой термин `Secret` уже
описан, колонка «Не использовать» уже содержит `Paste (в новом коде)`. Новых
терминов («schema-anchor», «rename») в предметной области нет; удаление
физического имени таблицы не является новым термином.

## Критерии приёмки (Given–When–Then)

> AC3 и AC5 зависят от Q1/Q2. Формулировки даны для **рекомендуемых вариантов
> Q1-A (оставить anchor, переименовать) и Q2-B (имена индексов `secret`-based)**;
> при других решениях они правятся на G1.

**AC1 — чистая БД: миграции дают `secret`.**
Given пустая тестовая БД;
When `php bin/console doctrine:migrations:migrate -n --env=test`;
Then все миграции применяются по порядку, после чего существует только таблица
`secret` (таблица `paste` отсутствует) с колонками
`id/token/hint/salt/nonce/ciphertext/created_at/expires_at`, unique-индексом на
`token` и индексом по `expires_at`; `doctrine:schema:validate --env=test` даёт
`mapping OK`, `schema in sync`, exit `0`.

**AC2 — сохранение данных на заполненной БД.**
Given БД на legacy-схеме `paste` с ≥3 строками, включая `hint = null`,
`hint <> null`, payload с нулевыми байтами и «дырки» в `id` (AUTOINCREMENT);
When выполняется `up()` новой миграции;
Then все строки присутствуют в `secret` с теми же `id`, `token`, `hint`,
`salt`, `nonce`, `ciphertext`, `created_at`, `expires_at` (побайтовое
равенство payload), число строк не изменилось, ни одна строка не добавлена/
удалена; следующая вставка получает `id` больше прежнего максимума
(последовательность AUTOINCREMENT не сброшена).

**AC3 — индексы согласованы с ORM-метаданными.**
Given миграция применена;
When сравниваются фактические индексы `secret` (`PRAGMA index_list`/`index_info`)
с индексами, которые строит `SchemaTool` из `SecretSchemaAnchor`;
Then множества имён и колонок уникального индекса `token` и индекса `expires_at`
совпадают; `SchemaValidator::schemaInSyncWithMetadata()` = `true` и
`getUpdateSchemaSql()` = `[]`.

**AC4 — миграция обратима.**
Given миграция применена на заполненной БД;
When выполняется `down()`;
Then существует таблица `paste` с прежними колонками/индексами и теми же
строками; повторный `up()` снова приводит к `secret` без ошибок и без потери
строк.

**AC5 — production-код использует `secret`.**
Given `src/`;
When ищется строковый литерал `paste` в SQL и именах классов;
Then SQL-запросы `DoctrineSecretRepository` обращаются к `secret`; отсутствует
файл/класс `PasteSchemaAnchor`; есть `SecretSchemaAnchor` с
`#[ORM\Table(name: 'secret')]` и согласованными именами индексов; mapping
`config/packages/doctrine.yaml` по-прежнему указывает на каталог `Schema/`;
имена колонок и `SecretRecordMapper` не менялись.

**AC6 — тесты синхронизированы.**
Given `tests/`;
When ищется `paste` как имя таблицы;
Then ни один тест не обращается к таблице `paste` (все — `secret`);
`PasteSchemaAnchorTest` переименован (например, `SecretSchemaAnchorTest`); есть
интеграционный тест миграции, закрывающий AC1–AC4; `make test` — 0 падений.

**AC7 — наблюдаемое поведение и публичные имена неизменны.**
Given существующие functional- и wiring-тесты;
When они выполняются;
Then пути `/`, `/p/{token}`, `/created/{token}`, wire-контракты
`create_paste[...]`/`unlock_paste[...]`, `csrf_token_id`, статусы, тексты,
`Cache-Control: no-store`, лимиты 10/мин, TTL и крипто-формат не изменились;
команда `app:paste:purge`, имена маршрутов `app_paste_*`, каталог
`templates/paste/*`, `#paste-url` и docker-том `paste_data` сохранены;
изменяются только ассерты, привязанные к имени таблицы.

**AC8 — качество и CI.**
When `make qa` (cs-check, PHPStan L10, deptrac, PHPUnit) и `make coverage`;
Then 0 ошибок; покрытие `src/*/{Domain,Application}` ≥ 90%; deptrac 0 нарушений;
новых `@phpstan-ignore` без причины/даты нет. CI-порядок
`migrate → schema:validate → phpunit` зелёный; `down()` также проверяется в CI

**AC9 — безопасность и безопасность миграции.**
Given логи, вывод миграции и тел ответов;
When анализируются;
Then `plaintext`, `SecretKey`, производные ключи, `salt/nonce/ciphertext` не

пересоздаёт таблицу с потерей строк; DDL-операции транзакционны на SQLite;

**AC10 — документы и трассируемость.**
When задача закрывается;
Then оформлен ADR по Q5 (при Q1-A — короткий ADR 0004 о переименовании и

## Открытые вопросы (и ответы человека)

> Статус: **G1 пройден (все рекомендации, Q2 = B).** Q1-A (anchor оставить,
> переименовать), Q2-B (`secret`-имена индексов), Q3-A (публичные имена не
> трогать), Q4-A (тест миграции up/down), Q5-A (ADR 0004), Q6-A (историю не
> редактировать).

### Q1 (блокирующий) — владелец ORM-схемы после переименования (закрытие Q1-C задачи 005)

- **A (рекомендую для 006). Оставить anchor, переименовать таблицу/класс.**
  `PasteSchemaAnchor` → `SecretSchemaAnchor`, `#[ORM\Table(name: 'secret')]`,
  имена индексов согласованы (Q2); `DoctrineSecretRepository` остаётся DBAL;
  `doctrine:schema:validate` сохраняется как гейт; `SchemaTool` в тестах
  продолжает работать. Миграция переименовывает таблицу и индексы.
  *Плюсы:* минимальный риск, один переход владения (уже сделан в 005), гейты не
  меняются; цель «схема = Secret» достигнута. *Минусы:* сохраняется дрейф двух
  представлений (N2/N6 ADR 0003), `paste`-имя уходит только из таблицы.
- **B. Migrations-only: убрать ORM полностью.** Удалить `SecretSchemaAnchor` и
  ORM-маппинг; схему создают только миграции. Тесты создают схему прогоном
  миграций (bootstrap), quality-гейт `doctrine:schema:validate` меняется на
  проверку «нет неприменённых/дрейфующих миграций»; ADR 0003 отменяется.
  *Плюсы:* соответствует долгосрочной цели (миграции — источник схемы), убирает
  дрейф anchor↔адаптер и B1-класс рисков (proxy/warmup). *Минусы:* меняет
  стандарт `QUALITY §4` и bootstrap **всех** интеграционных/functional-тестов
  (`SchemaTool` → миграции), теряется колоночная валидация ORM; обязателен ADR и
  отдельное одобрение; существенно шире 006 и смешивает два перехода в одной
  задаче.
- **C. Иное.** Например, оставить anchor, но отложить любые изменения имён
  индексов (см. Q2-A) или выполнить B отдельной задачей сразу после 006.

**Рекомендация:** **A** для 006. Q1-B считать предпочтительным долгосрочным
направлением, но вынести в отдельную задачу/ADR (например, после 006), чтобы
переименование схемы и смена владения не делались одним коммитом. Если человек
выбирает B уже в 006 — задача обязана включать ADR, смену QUALITY §4 и
переработку тестового bootstrap.

### Q2 — имена индексов после переименования

- **A. Оставить легаси-имена, закрепить их явно в anchor.**
  `idx_paste_expires_at` и `UNIQ_9C5678985F37A13B` явно указываются в
  метаданных. *Плюсы:* только `ALTER TABLE RENAME` (без перестроения индексов),
  минимальный и самый быстрый вариант. *Минусы:* `paste` остаётся в имени
  индекса; unique-имя — непрозрачный хеш.
- **B (рекомендую). Переименовать индексы в `secret`-based и закрепить явно.**
  Например `uniq_secret_token` (unique) и `idx_secret_expires_at`; миграция
  делает `DROP INDEX` + `CREATE ... INDEX` на `secret`, anchor объявляет те же
  явные имена. *Плюсы:* полное соответствие целевому словарю, детерминированные
  читаемые имена, снимает ловушку авто-хеша навсегда. *Минусы:* unique-индекс на
  `token` перестраивается (разовая O(n) операция, в транзакции).
- **C. Переименовать только `idx_secret_expires_at`, unique-индекс оставить
  легаси.** Компромисс между A и B.

**Рекомендация:** **B** — задача прямо ставит цель «привести имена/схему к
целевому словарю»; разовое перестроение индекса при самохостинге приемлемо и
обратимо. Если G1 приоритизирует минимальный риск на больших БД — A.

### Q3 — публичные/инфраструктурные имена `paste`

- **A (рекомендую). Отложить всё.** Маршруты `app_paste_*` (+ пути), команда
  `app:paste:purge`, wire-контракты `create_paste`/`unlock_paste`, `#paste-url`,
  `templates/paste/*`, том `paste_data` — без изменений. *Плюсы:* наблюдаемое
  поведение и ops-совместимость гарантированы; том `paste_data` не осиротит
  данные self-hosted. *Минусы:* легаси-термин в публичных именах остаётся до
  отдельной задачи.
- **B. Переименовать только внутреннее (не наблюдаемое):** каталог
  `templates/paste/*` → `templates/secret/*` и/или имена тестов; маршруты,
  wire, команда, том — без изменений. *Плюсы:* меньше `paste` в презентации;
  *Минусы:* дифф растёт, выгода косметическая.
- **C. Переименовать всё с обратной совместимостью** (алиасы маршрутов, старые
  wire-имена/описание команды, миграция тома). *Плюсы:* чистота имён.
  *Минусы:* ломает внешних потребителей и ops (scheduler/runbook/том),
  требует deprecation-плана; риск потери данных при переименовании тома.

**Рекомендация:** **A** для 006; B/C — отдельной задачей с планом совместимости.
Wire-контракты форм и имена маршрутов считаем наблюдаемыми (AC7).

### Q4 — как проверять сохранение данных миграции

- **A (рекомендую). Отдельный интеграционный тест миграции.** На изолированной
  SQLite-БД: seeding legacy-схемы `paste` + строк, прогон `up()` новой
  миграции, проверка строк/индексов/AUTOINCREMENT, затем `down()` и повторный
  `up()`. *Плюсы:* прямо доказывает AC2/AC4, воспроизводимо, ловит имена
  индексов. *Минусы:* нужен доступ к исполнению миграции в тесте (решает
  архитектор).
- **B. Полагаться только на CI-прогон миграций на пустой БД.** *Плюсы:* ничего
  нового. *Минусы:* не проверяет сохранение данных и `down()` — не закрывает
  AC2/AC4.
- **C. Ручная проверка на копии prod-БД.** *Плюсы:* реалистично. *Минусы:*
  нет автоматизации, не воспроизводится в CI.

**Рекомендация:** **A** (при необходимости дополнить ручной проверкой на копии
БД на G3).

### Q5 — ADR и смена гейта

- **A (рекомендую при Q1-A). Короткий ADR 0004** «Переименование `paste →
  secret` и политика имён индексов», дополняющий ADR 0003; стандарт качества не
  меняется. *Плюсы:* фиксирует раскрытую ловушку unique-имени и Q1-C.
- **B (обязателен при Q1-B). Новый ADR**, отменяющий/заменяющий ADR 0003,
  плюс правка `QUALITY §4` (гейт схемы) и тестового bootstrap.
- **C. Без ADR**, ограничиться plan/notes (если G1 считает решение чисто
  техническим исполнением ADR 0002/0003). *Минусы:* не фиксирует политику имён
  индексов и оценку риска отката.

**Рекомендация:** **A**.

### Q6 — трогать ли историческую миграцию

- **A (рекомендую). Не трогать `Version20260909000000`;** переименование — новой
  миграцией строго позже (например, `Version20260910000000`). *Плюсы:* история
  миграций неизменна, воспроизводима, безопасна для уже развёрнутых БД.
- **B. Отредактировать старую миграцию** (сразу создавать `secret`). *Плюсы:*
  меньше файлов. *Минусы:* ломает контрольные суммы/историю у существующих
  установок, не даёт проверить переименование, противоречит принципу
  «миграции неизменны».

**Рекомендация:** **A**.

## Нефункциональные требования и риски

### Нефункциональные требования

- **Сохранность данных:** миграция не теряет и не искажает строки; на проде
  выполняется после бэкапа `deploy.sh`; операция переименования — метаданные,
  перестроение индексов (при Q2-B) — разовое и транзакционное.
- **Обратимость:** `down()` восстанавливает точную предыдущую схему; повторный
  `up()` возможен. `QUALITY §5.6` («миграции применяются с нуля и
  откатываются»).
- **Поведение неизменно:** URL/маршруты, wire-контракты, тексты, коды,
  `no-store`, лимиты, TTL, крипто-формат — без изменений.
- **Среда:** минимальная поддерживаемая версия SQLite (≥ 3.25) проверяется и
  фиксируется; dev/test/prod дают одинаковую схему `secret`.
- **Границы слоёв:** deptrac 0; `Domain`/`Application` не импортируют
  Doctrine/DBAL/Symfony/Sodium.
- **Безопасность:** запрещено логировать/эмитить plaintext, `SecretKey`,
  производные ключи, `salt/nonce/ciphertext`; `.env.local` не добавляется.
- **Воспроизводимость:** чистая БД и БД с данными проверяются автоматически;
  `make qa` воспроизводим локально в Docker.

### Риски и меры

| Риск | Влияние | Мера |
|---|---|---|
| Потеря/искажение строк при rename | Утрата Secret | `ALTER TABLE ... RENAME` не переписывает строки; интеграционный тест AC2 (в т.ч. payload с NUL и nullable hint); бэкап в `deploy.sh` |
| `sqlite_sequence` не обновлён → коллизия `id` | Ошибка вставки/перезапись | AC2 проверяет, что следующий `id` > прежнего максимума; при дефекте — правка миграции |
| unique-имя меняется вместе с именем таблицы | `schema:validate` красный | Явные имена индексов в anchor и миграции (AC3); не полагаться на авто-хеш |
| Перестроение unique-индекса дорого на большой БД | Долгая миграция/блокировка | Разово и транзакционно; Q2-A как альтернатива без перестроения |
| Откат релиза после применённой миграции | Старый код ищет `paste`, БД — `secret` | `deploy.sh` бэкапит БД до миграции; задокументировать ручной `down()`/restore; вынести в plan как ограничение |
| SQLite < 3.25 | Rename недоступен | Проверить версию в образе и CI на этапе плана (DoD) |
| Расхождение сред `make test` (SchemaTool) и CI (миграции) | Ложно-зелёные/красные | AC1 (миграции) + AC6 (anchor/SchemaTool) + единые имена индексов |
| Дрейф anchor ↔ миграция (N2/N6 из 005) | `schema:validate` / данные | Явные имена + новый тест миграции; при желании закрыть N6 |
| Ошибочное переименование docker-тома `paste_data` | Осиротевшие данные self-hosted | AC7 фиксирует том как неизменный; запрет в out of scope |
| Ошибочное переименование публичных имён | Ломает wire/ops | Q3-A; AC7 |
| Устаревшие ADR 0002/0003/ARCHITECTURE §5 (`paste`) | Неверный источник правды | AC10 — актуализация в 006 (или явная пометка до 008) |
| Рост `@phpstan-ignore`/падение покрытия | Ослабление гейта | `make qa`/`make coverage`; ignore только с причиной/датой |

## Definition of Done (DoD) для задачи

1. Новая миграция применяется с нуля (AC1) и на БД с данными (AC2), обратима
   (AC4); `doctrine:schema:validate --env=test` зелёный (AC3).
2. `src/` не содержит SQL/классов с именем таблицы `paste`; anchor переименован
   (при Q1-A) и согласован с БД (AC5).
3. `tests/` не обращается к таблице `paste`; есть тест миграции; `make test`
   зелёный (AC6).
4. Наблюдаемое поведение и публичные/инфраструктурные имена (маршруты, wire,
   команда, шаблоны, том `paste_data`) не изменены (AC7).
5. `make qa` и `make coverage` зелёные; CI-порядок `migrate → schema:validate →
   phpunit` зелёный (AC8).
6. Секреты/payload не логируются и не эмитятся миграцией; миграция не разрушает
   данные (AC9).
7. ADR по Q5, `ROADMAP.md` и, где затронуто, ADR 0002/0003 и
   `ARCHITECTURE.md` §5 актуализированы; `docs/UBIQUITOUS_LANGUAGE.md` не
   изменён (AC10).
8. Артефакты — в `docs/task/006-rename-paste-table-to-secret/`.
