## Follow-up backlog

Пункты не входят в 002–008 и требуют отдельных задач; где указано — ADR.

### 1. Burn-after-reading

- **Что:** режим «одноразовый Secret»: флаг «одноразовый», признак «просмотрен»,
  удаление записи после первого `Reveal` в агрегате.
- **Почему отдельно:** не реализован в агрегате `Secret`; затрагивает инварианты
  домена, репозиторий/схему и контракт `RevealSecret`.
- **Триггер:** ADR (доменное решение) + миграция БД (новые колонки) + решение
  человека на G1/G2. Вне объёма 003 (G1 Q1-A).

### 2. Ops: автоматический откат/restore БД при деплое

- **Что:** `deploy/deploy.sh` не вызывает `down()`; при откате образа после
  применённой миграции `paste → secret` старый код обратится к таблице `paste`,
  которой уже нет. Нужен автоматический `down()` либо restore из бэкапа в
  `rollback()`.
- **Почему:** риск недоступности сервиса при неудачном деплое; сейчас есть
  только предмиграционный бэкап и документированный ручной откат.
- **Связь:** ADR 0004, §9 ARCHITECTURE; `COMPOSE_PROJECT_NAME_paste_data`.

### 3. Quality: тестовая инфраструктура и PHPStan

- **Что:**
  - базовый `TestCase` для functional/integration-тестов и/или
    `phpstan/phpstan-phpunit`, чтобы убрать растущий `@phpstan-ignore
    property.uninitialized` (11 шт. в тестах, причина/дата уже указаны);
  - при необходимости включить `migrations/` в PHPStan `paths`, если решим
    типизировать миграции (сейчас `paths: [src, tests]`, миграции вне анализа).
- **Почему:** `@phpstan-ignore` растёт из задачи в задачу; baseline не ведём —
  цель ноль ошибок. Тестовый bootstrap (`SchemaTool`) — кандидат на пересмотр
  при переходе на migrations-only.

### 4. Access: определение клиента и квоты

- **Что:** доверенные прокси и корректный `getClientIp()` (сейчас
  `getClientIp() ?? 'unknown'`, без `X-Forwarded-For`/trusted proxies);
  квоты/лимиты для аккаунтов и контекст `Identity`/`Quota`.
- **Почему:** явно вынесено из 007 (Q6-A); при появлении `Identity`/`Owner`
  лимиты должны учитывать владельца, а не только IP.
- **Связь:** §3.1/§3.2, `docs/QUALITY.md` §2.2 (`Access_*`).

### 5. Полное переименование публичных имён в `Secret`

- **Что:** команда `app:paste:purge`, маршруты/имена `app_paste_*`, wire-формы
  `create_paste`/`unlock_paste` и `csrf_token_id`, `templates/paste/*`,
  DOM-id `#paste-url`, docker-том `paste_data` — привести к `secret`.
- **Почему:** остаётся последним следом legacy-термина в публичной
  поверхности; на первом шаге URL/wire-контракты не меняются, поэтому задача
  разбивается на совместимые шаги.
- **Связь:** ADR 0004 (Q3-A), §9 п.2, `docs/UBIQUITOUS_LANGUAGE.md`
  («Переходные публичные имена»).

### 6. Владение схемой (открытый долг)

- **Что:** migrations-only — удаление ORM schema-anchor `SecretSchemaAnchor`,
  переход тестового bootstrap на миграции, пересмотр `docs/QUALITY.md` §4
  (`doctrine:schema:validate`).
- **Почему:** двойное представление схемы (anchor ↔ DBAL SQL) — источник
  дрейфа; отложено в 005/006 (ADR 0003/0004, Q1-C).
- **Триггер:** отдельный ADR и гейт G2.

### 7. Прочее (оркестратор)

- Уточнить формулировку `ROADMAP.md` §007 «интеграция в use case'ы»: фактически
  порт `Access` вызывается из Presentation (решение 007 Q2-A). Правка roadmap —
  в зоне оркестратора, в 008 не выполнялась.
